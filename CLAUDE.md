## Overview

Personal website (dankennedy.ie) — a static single-page site served via nginx in a Docker container.

## Architecture

A single page, no subpages.

- `src/index.html` — one `<section class="screen">` per screen (`data-img` = its pixel image, optional `<article class="page">` write-up, `data-detail` = the full-res version faded in while reading it)
- `src/main.js` — screen navigation (arrows/keys/wheel/swipe), background crossfade, reading view, name wipe. Screen images must all share one size (`IMG_W`/`IMG_H`); the live hand is positioned over its render via `HAND_RECT`
- `src/hand.js`, `src/nozzle.js` — `mountHand` (URDF hand, the hand screen's full-res layer) and `mountNozzle` (wireframe revolved from `public/nozzle/contour.csv`, inline in the nozzle write-up). Lazy-loaded with three.js when their screen is first landed on
- `src/characteristics.js` — crisp nozzle chart for the reading view; layout constants mirror `scripts/characteristics.py`
- `src/render-hand.html` — dev-only page (not built) that `scripts/make-art.sh` screenshots to make `hand.png`
- `assets/` — **gitignored** private source photos; never copy them into `public/`. Screen images in `public/images/screens/` are generated by `scripts/make-art.sh`: it renders the hand via headless Chrome, `scripts/dither.py` ordered-dithers the opening farm screen to 8 colours pooled from the photo and the rest to greyscale (one blue accent on the hand render), and `scripts/characteristics.py` draws the nozzle screen from `public/nozzle/characteristics.csv`. Only reduced images ship (plus `cows-full.jpg`, a greyscale crop)
- `public/` — static assets served as-is (favicons, webmanifest, screen images, URDF + meshes, characteristics CSV)
  - `public/style.css` — hand-written CSS (no build step); colours are the `:root` variables. `--accent` must match the accent in `scripts/make-art.sh` and `scripts/characteristics.py`
- `package.json` — Vite (dev), three, urdf-loader
- `Dockerfile` — multi-stage: node build → nginx serve from `dist/`
- `.github/workflows/build.yaml` — CI/CD pipeline triggered on push to `main`; `deploy.yaml` — manual prod deploy

## CI/CD Pipeline

Pushes to `main` (excluding `bump:` commits) trigger:
1. Commitizen version bump + CHANGELOG update (committed back to the branch)
2. Docker image built and tagged with the new semver + `latest`
3. Image pushed to GHCR (`ghcr.io/<repo>`)

## Commits

This repo uses **Conventional Commits** enforced by Commitizen (`cz_conventional_commits`). Always use conventional commit format: `feat:`, `fix:`, `chore:`, etc.

## Local Development

```bash
npm install
npm run dev      # Vite dev server at http://localhost:5173
npm run build    # outputs to dist/
npm run preview  # preview dist/ locally
```

To preview via Docker (mirrors production):

```bash
docker build -t dankennedy-ie .
docker run -p 8080:80 dankennedy-ie
# Open http://localhost:8080
```
